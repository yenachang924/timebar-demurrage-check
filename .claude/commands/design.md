`docs/brief.md`를 바탕으로 워크플로를 설계한다. 추가 조건: $ARGUMENTS

workflow-architect 에이전트에게 설계를 맡기고, 결과를 `docs/design.md`에 정리한다. 이미 있으면 바뀐 부분만 고치고 맨 위에 버전과 바꾼 이유를 한 줄 적는다.

`docs/design.md`에 들어갈 것:

- 노드 순서 표 (노드 / 종류 / 입력 / 출력 / 고른 이유)
- **출력 키 표** (키 / 타입 / 허용 값·형식 / 예시) — 정답지 `output_keys`가 될 목록
- 예외 경로 표 (상황 / 감지 노드 / 내보내는 값)
- 각 노드에 넣을 프롬프트·추출 스키마 초안 (사용자가 Studio에 붙여넣을 수 있게)
- 설계서 네 칸 초안 (2쪽 분량에 맞게)

출력 키를 정할 때:

- 채점 키는 값이 하나로 정해지는 것만 둔다 (판정 값, 숫자, 날짜, 코드, 목록). 문장으로 된 사유는 다시 실행하면 달라지므로 채점 키에서 뺀다.
- 키 이름은 한 번 확정하면 바꾸지 않는다. 이번이 변경이면 workflow·정답지·설계서·유형표 중 무엇을 같이 고쳐야 하는지 목록으로 알려준다.

`submission/`에 정답지 JSON이 이미 있으면 `output_keys`를 새 설계와 맞추고 `uv run python tools/check_submission.py`를 돌려 결과를 보여준다.

Studio 노드의 실제 설정 항목 중 확인하지 못한 것은 `미확인`으로 표시하고, 사용자에게 Studio에서 무엇을 보고 알려달라고 할지 구체적으로 적는다.
